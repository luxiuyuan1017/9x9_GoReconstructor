# 开发中踩过的坑与易错点

本文记录实现本项目（9 路终盘棋谱重建原型）过程中**实际踩到**、并且值得以后小心的点。
每条都给出：现象 → 为什么错 → 正确做法 → 本仓库里的位置。

内容按主题分：坐标/格式、围棋规则、KataGo 引擎、loss 建模、输出与绘图。

---

## 0. 先记住三个教训

1. **不要相信"库的坐标就是我的坐标"** —— 棋盘库的轴向、原点、行列顺序都可能是反的，
   而且它不会报错，只会把你的盘面悄悄转置。
2. **不要用手搓的局面验证规则** —— 手搓局面很容易摆出"其实不合法"或"其实不符合预期"
   的形状，于是测试失败会被误判成代码 bug。**用真实棋谱重放**做验证。
3. **规则实现要把"最后一气"这类细节想清楚**，直觉（"提子一定发生在落子点旁边"）是错的。

## 1. 坐标与 SGF 格式

### 1.1 sgfmill 的坐标轴向与内部约定相反（最严重的一次）

- **现象**：由 `get_setup_stones()` 生成的局面 SGF，写出来再读回，盘面是真实终盘的
  **转置**（`(r,c)` 与 `(c,r)` 互换），棋子里数还对得上，很容易蒙混过关。
- **为什么错**：sgfmill `Board` / `get_setup_stones()` 返回的整数元组，其轴向与
  "行从上往下、列从左往右"的约定不一致。直接当成 `(row, col)` 用就转置了。
- **正确做法**：把 sgfmill 只当 **SGF 语法解析器**。摆子与着手都从 **SGF 坐标字符串**
  转成本项目内部坐标：
  - `AB`/`AW` 用 `node.get_raw_list("AB")` 拿原始值；
  - 着手用 `node.get_raw_move()` 拿原始坐标。
- **位置**：`gorecon/sgf_io.py` 的 `_split_setup()` / `load_game_record()`。

### 1.2 sgfmill 对某些属性返回 `bytes` 而不是 `str`

- **现象**：`sgf_to_point(b'ee')` 抛 `ValueError: 非法 SGF 坐标`。
- **正确做法**：统一过一层 `_as_text()`（`bytes` → `ascii` 解码）。
- **位置**：`gorecon/sgf_io.py::_as_text`。

### 1.3 `get_setup_stones()` 返回的是三元组，不是成对列表

- **现象**：`for colour, points in node.get_setup_stones()` 静默跑成 `set()`，什么都不做。
- **正确做法**：它是 `(黑集合, 白集合, 空集合)`。
- **位置**：`gorecon/sgf_io.py`。

### 1.4 `AB`/`AW` 没有值时不是合法 SGF

- **现象**：为了表示空盘写出 `AB`（无方括号）→ 读回时报 `property with no values`。
- **正确做法**：没有任何棋子时索性不写 `AB`/`AW`；同时意识到"无棋子局面"本身是退化输入
  （没有东西可重建），生成数据时直接跳过第 0 手。
- **位置**：`gorecon/sgf_io.py::position_to_sgf_text`，
  `prior/from_manual_to_situation.py`。

### 1.5 pass 的表示是空字符串，不是 `None`

- **现象**：`if sgf_point is None` 漏掉了 `W[]`，后续抛的是"非法坐标"而不是"不支持 pass"。
- **正确做法**：判 `sgf_point in (None, "", b"")`。
- **位置**：`gorecon/sgf_io.py::load_game_record`。

### 1.6 SGF 坐标字母表里第一个字母可以是 `#`

- **现象**：`#` 是字母表第 0 位，所以"空盘局面"其实能用一个奇数坐标表示。
- **正确做法**：用坐标表时不要假设"第一个字符一定在 a..i 之内"；判空局面靠"有没有棋子"，
  不靠坐标值。

### 1.7 GTP 列名跳过 `I`，SGF 不跳过

- **陷阱**：9 路 GTP 是 `A..J`（无 `I`），右下角是 `J1`；SGF 是 `a..i`，右下角 `ii`。
  两者之间转换必须集中处理，不要散落在业务代码里。
- **位置**：`gorecon/board.py::gtp_to_point` / `point_to_gtp` / `sgf_to_point` / `point_to_sgf`。

### 1.8 KataGo policy 的下标顺序

- 盘面部分按**从左上到右下的行优先**排列，长度 `size*size`，**最后一项是 pass**。
  对 9 路即 `policy[row*9 + col]`，长度 82。
- **位置**：`gorecon/board.py::policy_index_to_point`。

## 2. 围棋规则

### 2.1 被提棋块的最后一气不一定与落子点相邻（很容易写错）

- **错误实现**：只检查"落子点相邻的对方棋块"是否无气。
- **反例**：白 `(0,0)`，黑 `(0,1)`、`(1,0)`，黑落 `(0,2)` 应提白 `(0,0)`
  —— 但白的气是 `(0,1)(1,0)`，与落子点 `(0,2)` **不相邻**，上面的实现漏提。
- **正确做法**：必须**先在落子点完成落子**，再检查该点相邻的对方棋块是否因此无气。
  不要试图在落子前就判断谁能被提。
- **位置**：`gorecon/board.py::place_stone`。

### 2.2 自杀判断要在提子之后做，且不能只看有没有提子

- **错误实现**：`if not captured: 再查气 == 0 才判自杀`。
- **问题**：提子与自杀不是互斥的二分；应当无条件地"落子 → 提掉相邻无气对方块 →
  再查自己这块的气"。气为 0 才是自杀（此时必然没有提子）。
- **位置**：`gorecon/board.py::_position_after` / `play` / `is_legal`。

### 2.3 "同一盘面可以由不同历史达到"

- 不许按盘面哈希把不同历史合并；缓存键必须包含**完整历史**。
- **位置**：`gorecon/katago_loss.py::KataGoEngine._cache_key`。

### 2.4 落子只会减少某色的场上棋子数

- 由此得到安全剪枝：目标还缺的某色棋子数，不能超过**该色**剩余可落子次数。
- **位置**：`gorecon/heuristic_search.py::_prune`（该文件为搜索环节保留，超出 prior 三任务范围）。

### 2.5 不要用"剩余手数 ≤ 空点数"剪枝

- **为什么错**：被提的位置可以再下，9 路对局总手数可以超过 81。这条限制会误删可行路径。

### 2.6 剩余手数必须按颜色分配（按轮次奇偶）

- **错误实现**：用 `(remaining + 1) // 2` 一律当成黑方剩余手数。
- **后果**：在"该白方下"的层多算一手，把本可成功的路径误剪。
- **正确做法**：第 `turn + 1` 手是黑方 **当且仅当** `turn` 为偶数。

## 3. KataGo 引擎

### 3.1 首次运行会做 OpenCL GPU 自动调优，看起来像"卡死"

- **现象**：`katago analysis` 启动后长时间无输出，CPU 占用高、GPU 占用高，
  位置停在 `Tuning k/N`。本机（Intel UHD 核显 + b15c192 模型）约 **10 分钟**。
- **正确做法**：不要误判为死锁。调优结果会写入
  `KataGoData/opencltuning/tune13_gpu<型号>_x<盘>_y<盘>_c<通道>_mv<...>.txt`，
  **写完之后**再启动只需数秒。用带时间戳的 stderr 转发就能看清它到底停在哪一步。
- **位置**：`gorecon/katago_loss.py::KataGoEngine._wait_ready`（启动超时设得足够大）。

### 3.2 `policy` 是概率，不是 log 概率

- **现象**：一度看到 `sum(policy) = -1.0`，差点据此改成 `exp(policy)`。
- **真相**：那是 `nnRandomize=true` 下的异常返回。稳定复现时 `policy` 和为 `1.0`，
  就是概率本身。
- **正确做法**：先打印 `sum(policy)`、`min/max` 确认语义再写公式；
  别急着加 `exp`。
- **位置**：`gorecon/katago_loss.py::KataGoResult.pointwise_loss`。

### 3.3 `nnRandomize=true` 会让同一查询结果不可复现

- **现象**：同一个局面、同一手，两次运行给出不同的概率（0.36279 vs 0.39140），
  "损失值"每次都不一样。
- **正确做法**：在覆盖配置里显式 `nnRandomize = false`，做损失分析要可复现。
- **位置**：`config.toml` 的 `[engine] overrides`。

### 3.4 非法点的 policy 是 0，不能直接取对数

- 非法点在 policy 里为 0（或缺失），`-log(0)` 会炸。应剔除非法点，
  合法点再用可配置的数值下限兜底（`prob_floor`）。

### 3.5 每手的分数必须从"落子前"的父局面取

- 在落子之后查询，那个点已经**被占据**，拿到的分布不再对应"预测这一手"。
- 本项目的约定：第 `n` 手（1 基）的损失由"第 `n-1` 手之后"的局面给出。
- **位置**：`prior/output_katago_loss.py::analyse_move`。

### 3.6 一次局面查询即可拿到全部落点概率

- 不要对每个子落点重新启动引擎或分别推理。一个局面一次查询，缓存键含完整历史。

## 4. loss 建模

### 4.1 终盘 loss 只能由**终局**生成，不能按手数取中间局面

- **我犯过的错**：把"要重建第 25 手"理解成"目标局面取第 24 手之后"，
  于是用了中间盘面去算固定终盘代价表。
- **为什么错**：终盘是唯一已知的局面，中间任何一手的盘面都不可获取。
  用中间局面等于用了不该有的信息，产出的热图无效。
- **正确做法**：固定终盘点位代价表由终局在整张棋盘上算**一次**，整次搜索不变。
  要重建第 n 手时，**目标局面**取"第 n 手之前"，但**代价表**里的"终局"信息仍然指终局本身；
  两者不要混为一谈。
- **位置**：`prior/output_reconstruction_loss.py`（只接受 `--situation` 或 `--sgf`，
  刻意**不提供** `--move`）。

### 4.2 终盘代价表的档位关系（容易被直觉带偏）

以"当前准备落子的颜色"看终局信息：

| 终局信息 | 代价 | 说明 |
| --- | --- | --- |
| 同色棋子 | **0** | 全局唯一最小值；每放对一个子，总代价就减 1 阶 |
| 对方棋子 | 适中、有限 | 这是搜索把棋子**放对位置**的主要路径（对方子被提掉后才能变同色），不能设成最贵 |
| 对方棋子，且该点在本方团块内部 | 更低一档 | 团块内部很可能是提子发生处，历史上更可能真放过对方的子；角/边/常规分三档配置 |
| 空、空区只被对方完全包围 | 基础罚分 + 面积 × 系数 | 小面积**适中**，随面积线性增长；不要预设一上来就很大 |
| 空、其余（自己完全包围 / 中立空区） | 大而有限 | 往自己的空里或中立空区填子都不可能是历史 |

三个反复踩到的判断错误：

- **误以为"除同色外每档都很大"**：其实对方包围的小面积区域应当是**适中**的，
  由面积决定；把它设得很大同样会扭曲搜索。
- **把"自己包围的空区"和"中立空区"混进"其他空点"共用一个小罚分**：
  于是搜索被**鼓励**往自己空里填子，方向完全反了。
- **漏掉"团块内部"这一档**：同色团块内部的点，历史上很可能是对方先下在这里、
  被提掉、再被本方反提。所以该点处**对方**的代价应当更低，而不是和普通异色点一样。

#### "团块内部"的判定细节

定义：**该点相邻的全部（在盘内的）棋子都是同色**。

- 角上只有 2 个邻点、边上 3 个、其余 4 个 —— 只看在盘内的邻点，**角、边也算内部**，
  不要写成"必须凑满 4 个邻点"，否则角边永远判不出来。
- 有一个邻点是空点或对方棋子，就不是内部。
- 角 / 边 / 常规三档**分开配置**（虽然本版取同值）：不同位置出现对方棋子的概率可能
  不同，便于后续分别调整。
- 抽查方式：把真实终局里判为内部的点连邻点一起打印出来核对。本仓库真实终局里
  黑有 3 个内部点（`bd`、`hd`、`ef`），白 0 个。

另外必须记住：

- **加权系数 λ 会缩放整档**：`λ=0.5` 时"基础 4 + 面积 0.5a"实际输出 2..12.5。
  讨论档位大小时要把 λ 算进去，否则会以为参数没生效。
- **罚分必须有限**：终局属于自己的子也可能在这条重建历史里被提掉后补回来，
  无限代价会剪掉合法路径。
- **空区连通要看"棋盘边缘只当边界"**：边缘不是一种棋子颜色；
  同时接触黑白、或完全不接触棋子的空区，都不算被任何一方完全包围。

### 4.3 中立空区虽然少见，但不能给它低代价

一般终局不该有中立空点；若出现，说明双方都没把棋走活透，在那里填子同样离谱，
所以要给大罚分，而不是"比对方包围区还便宜"。

### 4.4 不要把"最近似终盘"的棋谱当成成功输出

预算内没找到逐点一致的结果，就要明确报"未找到匹配棋谱"。
终盘匹配是**逐点颜色一致**，不是目数接近、胜率接近或棋子数相同。

## 5. 输出与绘图

### 5.1 不要在热图上叠画棋子

棋子会**盖住格内的损失数值**。损失热图的目的是看每个点的代价，棋子属于另一层信息，
需要时另画一张盘面图。

### 5.2 长标题会被画布裁掉

用完整文件名当标题，两侧文字会被切掉。标题要么短、要么不画；
需要完整来源信息就写进 JSON。

### 5.3 中文字体要显式指定

matplotlib 默认字体（DejaVu Sans）没有 CJK 字形，中文会被吞掉并刷一屏
`Glyph ... missing from font(s)` 警告。显式设置
`font.sans-serif = ["Microsoft YaHei", "SimHei", ...]` 并 `axes.unicode_minus = False`。

### 5.4 Windows 控制台默认编码可能编不出中文

在 cp932/GBK 控制台下打印中文日志会直接抛 `UnicodeEncodeError` 让脚本崩掉。
命令行入口先 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。

### 5.5 用 `Select-Object -First N` 截断 Python 输出会把它杀掉

- **现象**：`python ... | Select-Object -First 30` 之后 `$LASTEXITCODE = -1`。
- **原因**：管道下游提前关闭，Python 收到断管被终止 —— 这**不是**脚本失败。
- **正确做法**：判断退出码时把输出重定向到文件再读，不要中途截断管道。

### 5.6 两个脚本对同一棋谱用同名输出会互相覆盖

任务2 与任务3 都按 `<棋谱名>_moveNNN` 命名时，后跑的会把前一个的图覆盖掉。
给不同用途的文件加语义后缀（`_reconstruction`、`_terminal`）明确区分。

## 6. 数据制作

### 6.1 输入必须**重放后新建**只含终盘的摆子 SGF

不能直接把完整棋谱当输入。读取端应当**明确报错**（"含 B/W 着手属性，这是棋谱而不是局面"），
防止把答案当输入。原始顺序可以另存，但只用于评测。

### 6.2 同一盘棋的不同截断属于同一集合

按整盘对局划分调参与测试集；同盘的截断或对称版本放在同一集合，不要跨盘混用。

### 6.3 不能拿模型自己的 loss 变小当作"恢复更准确"的证据

需要用独立重放校验：输出 SGF 重放后与目标**逐点一致**，并满足已知的手数/轮次约束。

## 7. 快速自检清单

实现或改完一个环节后，按这个顺序过一遍最省时间：

1. 坐标：SGF `aa/ai/ia/ii` ↔ 内部 ↔ GTP（跳 `I`）三个方向都往返一遍。
2. 提子：提单子、提多子、一手提多块、**最后一气与落子点不相邻**、边角提子。
3. 规则：自杀被拒、占用点被拒。
4. 盘面：由真实棋谱逐手重放，每手后"落子数 − 被提数 = 现存活子数"逐色成立。
5. 空区：面积、边界颜色、有没有被单色完全包围；棋盘边缘不算颜色。
6. 终盘 loss：同色点恒为 0 且是全局最小；空点严格大于 0；对方包围区随面积单调增；
   团块内部异色点代价 < 普通异色点代价；角/边/常规三档都能被触发。
7. 引擎：`sum(policy) == 1`；重复查询结果一致（`nnRandomize=false`）；
   每手从落子前局面取分。
8. 输出：热图数值可见（不叠棋子）、标题不裁切、两个任务的图不互相覆盖。
