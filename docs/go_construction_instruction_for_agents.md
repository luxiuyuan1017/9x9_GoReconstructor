# 给 Codex 的项目说明：基于冻结 KataGo 的围棋终盘棋谱推断

请依据本文实现一个最简、可运行、可验证的 Python 原型。本文是讨论后收敛的最新需求；优先实现下述核心，不必沿用此前较大的目录骨架。

## 1. 项目目标与已确定的核心

输入一份只含棋子分布的9路局面 SGF，从空盘开始按黑白交替进行正向启发式搜索，输出能够合法重放到该局面的棋谱 SGF。

虽然任务是在推断过去的棋谱，搜索本身采用正向展开，以直接利用 KataGo 的正向落子预测能力。

模型不重新训练 KataGo，也不从零训练逆向网络。核心只有两类搜索代价：

1. 终盘棋型 loss：由输入终盘生成，黑、白各一张固定点位代价表，全局计算一次。
2. KataGo loss：由本地、冻结的 KataGo 对当前候选棋谱预测下一手概率，转换为点位代价，每个候选局面分别更新。

搜索采用按层启发式搜索（heuristic search）。n 表示每层最多保留的活动候选棋谱数量。将本层所有父节点展开得到的候选合并，按累计 loss 从小到大统一保留 n 条。

“loss”在这里是搜索代价，不要求可微，也不要求反向传播。终盘通常不能唯一确定原始历史，因此输出是搜索到的高可信候选，不应声称必然还原了真实唯一棋谱。

## 2. 首版范围

已确定的范围：

- 9路棋盘，空盘开始、黑先、双方交替。
- 允许普通提子，包括提单子、提多子及一手提多块。
- 输入局面由用户手动提供，并确认其来源棋谱无劫争。
- 只搜索落子，不将停手、认输等终止动作作为恢复目标。输入是最后一次实际落子后的原始盘面。
- 暂不做图片识别、GUI、棋力等级建模、Human SL 接入、自动调参或网络训练。

建议将规则固定为中国规则，贴目由输入或配置明确给定。按常规规则处理非法着手，不拓展特殊自杀规则。

## 3. 输入与输出

### 输入：单节点局面 SGF

采用 SGF FF[4]，使用 AB 和 AW 设置棋子位置；不提供真实的 B/W 着手序列。

示例只用于说明格式，不代表实际完局：

```sgf
(;FF[4]GM[1]CA[UTF-8]SZ[9]RU[Chinese]KM[7.5]
AB[ha][ia]
AW[ah][ai][bi]
)
```

其中，FF 表示格式版本，4 表示第四版；GM 表示游戏类型，1 表示围棋；CA 表示文本编码，此处为 UTF-8；SZ 表示棋盘大小，此处为9路；RU 表示规则，此处写 Chinese；KM 表示贴目，此处为7.5；AB 是黑棋摆子列表，AW 是白棋摆子列表。括号包围棋谱树，分号引入一个节点，方括号包含属性值。

SGF 坐标第一个字母为列，从左到右；第二个字母为行，从上到下。9路使用 a 到 i；aa 是左上，ii 是右下。上述示例的 ha、ia 是顶行右侧两点，ah 是左侧倒数第二行，ai、bi 是底行左侧两点。AB/AW 列表顺序不携带历史先后。

实现要求：

- 首版要求输入恰好一局、一个摆子节点；遇到包含 B/W 着手或子树的完整棋谱时明确报错，提示先转换成局面，防止误用答案。
- 校验坐标、棋盘大小、黑白重叠及局面合法性；不要让解析库悄悄修改输入盘面。
- 只有明确出现 PL 时，才将其作为已知的目标轮次约束。PL[B] 表示轮到黑方，PL[W] 表示轮到白方；缺失时视为未知，不把软件默认值当作真实已知信息。
- 搜索起点仍为空盘，不把目标 AB/AW 传成对局的初始摆子。
- 总手数作为独立可选参数 known_moves。未知时不从隐藏答案中补全。
- 输入与配置的规则或贴目冲突时，明确提示；不得静默使用不一致规则。

### 输出：候选棋谱 SGF

成功时输出从空盘开始的真实着手节点序列，使用 B 和 W 属性记录搜索生成的落子。保留正确棋盘大小、规则、贴目等信息。输出后再独立重放一次，确认最终黑白棋子位置与输入逐点一致，并满足已给定的手数和轮次约束。

可额外保存多个排序候选与简单日志，但最少应有一份最佳候选 SGF。搜索预算内未找到解时，明确返回“未找到匹配棋谱”；不能把最接近终盘的棋谱冒充成功输出。

## 4. 子程序一：固定终盘点位 loss

建议模块 terminal_loss.py；建议入口 build_terminal_loss，输入目标棋盘和可配置参数，输出黑棋、白棋各一张9路大小的浮点代价表。它是逻辑子程序，不要求独立常驻进程或每次写磁盘。

计算一次后，在整次搜索中保持不变。可附带保存终盘空区面积和边界颜色，便于解释罚分。

固定空区定义：在目标终盘中，用上下左右连接划分完整空区。统计每个空区相邻棋子的颜色集合，棋盘边缘只充当边界，不是一种棋子颜色。仅接触黑棋的空区视为被黑方包围，仅接触白棋的空区视为被白方包围；接触双方或完全没有接触棋子的空区不判为任何一方完全包围。

首版建议规则如下，具体权重是待验证的实现默认值，不是已经证明有效的参数：

| 当前准备落子的颜色与该位置的终盘信息 | 固定点位代价 |
| --- | --- |
| 终盘为同色棋子 | 0 |
| 终盘为空，且所在完整空区只被对方包围 | 临时落子基础罚分，加上随该空区面积增加的罚分 |
| 终盘为空，但不属于上一类 | 较高、可配置且有限的罚分 |
| 终盘为对方棋子 | 可配置且有限的临时落子罚分 |

面积项先采用线性形式：空区面积乘以面积系数。后续再研究更合适的曲线，不在首版加入额外学习模型。

用户的直觉是，大空区中的临时落子可能意味着较大规模提子，应降低其优先级。这只是先验，终盘空区面积与真实某次提子规模不必完全相同，不能据此硬断言历史。

重要边界：

- 不能把“终盘不是同色”的所有位置设为无限代价，因为这些棋子可以在后续被提走。
- 不能只允许在终盘空点中出现临时棋子：某点也可能先落黑子被提，最后落白子。
- 候选生成首版直接遍历当前所有合法交叉点，通过有限罚分排序；暂不做依赖终盘包围形状的排他性落点屏蔽。
- 终盘代价表不是当前合法性表。当前占据、禁入等由规则执行器和当前引擎结果判断。
- 该项会按每次落子累积；应记录分项，观察同一空区反复计费是否过强。
- 讨论过的“实际提子数平方惩罚”不属于这次最简核心，不默认额外加入。

## 5. 子程序二：动态 KataGo 点位 loss

建议模块 katago_loss.py；建议入口 compute_katago_loss，输入当前候选的完整历史、规则和贴目，输出当前落子方的点位代价与合法点信息。无需每步同时计算黑白双方两张动态图。

采用本地 KataGo 的 JSON analysis 接口，模型权重冻结。首版使用普通模型的原始 policy，不以胜率、目数、搜索访问次数或一选排名代替落子概率。

建议行为：

- 启动一个常驻 KataGo 进程，通过配置指定可执行程序、模型和官方分析配置路径。
- 每条查询传入候选的完整 moves 历史和匹配的规则、贴目，请求 includePolicy；初筛可采用很小的搜索预算。
- 每个不同候选局面分别查询；可批量发送，不同请求用唯一 id 匹配结果。
- 一次局面查询获得全部落点概率，不要对每一个子落点重新启动引擎或分别推理。
- 显式关闭 ignorePreRootHistory，保留候选历史对预测的影响；与所安装版本的官方文档核对设置方式。
- 对合法点取概率的负自然对数，作为动态点位 loss。对过小的合法概率采用可配置数值下限。
- 非法点的 policy 标记不能直接取对数，应剔除；本地规则仍需独立检查。
- 原始 policy 的最后一项是 pass。首版不展开 pass，也不因为剔除了 pass 或筛选候选而重新归一化用于路径评分的原概率。

缓存属于可选优化。若实现，键必须包含影响预测的模型、配置、规则、贴目、轮次和历史；最简单安全的方案是用完整候选历史作为键的一部分。不要仅按盘面合并历史相关评分。

## 6. 单步与累计代价

终盘项与 KataGo 项采用加权相加，KataGo 项系数先固定为1：

\[
C\bigl(H\oplus(c,x)\bigr)
= C(H)-\log p_K(x\mid H,c)+\lambda L_{\mathrm{终盘}}^{c}(x).
\]

其中，C 是候选棋谱的累计代价；H 是当前候选历史；追加符号表示在该历史后增加一手；c 是本手颜色；x 是落点；p_K 是冻结 KataGo 在给定历史和颜色时预测该落点的概率，K 表示所用模型；竖线表示条件；log 是自然对数；lambda 是终盘代价的整体系数；L 是固定终盘点位代价，上标 c 只表示选择黑棋或白棋对应的表，下标“终盘”表示该表由目标局面生成。

每手的 KataGo 分数必须从“落子前”的父历史取得，不能在落子后查询该已经被占据的位置。每个节点分别记录累计 KataGo 项、累计终盘项和总分，便于排查异常。

首版不额外加入终盘距离 loss。若以后添加“还缺多少目标棋子”等搜索启发，应与上述最终路径代价分开记录，不能静默改变本版定义。

## 7. 启发式搜索的精确流程

建议模块 heuristic_search.py。

1. 读取目标局面，计算黑白固定 loss 表。
2. 以空棋盘、空历史、黑方落子、累计代价为0初始化活动候选。
3. 对本层每个父候选获取动态 KataGo 点位 loss。
4. 枚举当前所有合法交叉点，复制或安全派生棋盘状态，执行落子及提子。
5. 用父节点累计代价，加上本手两项代价，得到子节点累计代价。
6. 已精确达到目标且满足已知元信息的子节点进入完成结果池。
7. 其余所有合法子节点合并为同一个池，按累计代价保留最多 n 条活动候选。
8. 重复直到活动候选耗尽或达到手数、时间、引擎调用等预算，返回已找到的最低代价完成候选。

实现时务必保证：

- 排序依据是整条历史的累计代价，不是仅看最新一手。
- n 是全局每层上限，不是每个父节点分别保留 n 条。
- 首版不额外加入每父节点策略前若干名截断；9路可先完整枚举合法点，减少排查“真实落子根本没进入候选池”的干扰。
- 不同候选棋盘状态互不污染；试探一手后的提子不能修改兄弟节点。
- 同一盘面可能由不同历史达到。最简实现不要仅按棋盘哈希把历史直接合并。
- 完成候选另存，不需要反复扩展。输出是启发式搜索预算内找到的候选，不宣称全局最优。
- 终盘匹配是逐点颜色一致，不是目数相近、胜率相近或只有现存棋子数相同。

## 8. 手数与停止条件

max_moves 是最大搜索落子手数，必须可配置。棋盘有81个交叉点不意味着对局最多81手，因为被提的位置可以再下。

可选 known_moves 是外部明确给定的总落子手数。提供时，只接受该手数处的匹配盘面，并可加入安全剪枝；未知时不能从输入终盘占子数推断精确总手数。

已知手数时可以实现以下可选严格剪枝：

- 目标还缺的某色棋子数，超过该色剩余可落子次数。
- 已累计被提的某色棋子数，超过由总落子次数和终盘存活棋子数推得的额度。

这些剪枝不属于额外 loss。未知手数时不要使用依赖精确手数的额度。

未知手数的完整候选使用当前累计代价比较，日志应说明这种设定可能偏向较短历史；首版不要自行改成逐手平均 loss。手数先验可留待后续实验。

## 9. 规则、坐标及复用现有库

主搜索程序仍需要维护当前棋盘和执行提子的组件。两个 loss 子程序不替代围棋规则执行器，但规则组件也不必是第三个外部程序。

可优先考察 sgfmill，用于 SGF 解析、合法棋谱重放、提子和摆子/棋谱输出，避免重复实现SGF语法。注意它的 Board.play 会执行提子；其他合法性约束仍需结合所选规则检查。对输入局面也应校验，避免某些摆子函数自动移除无气棋块后悄悄改变目标。

建议内部统一使用“行从上往下、列从左往右、第0行第0列位于左上”的坐标约定，并把外部坐标转换集中处理：

- SGF 左上为 aa，右下为 ii，字母连续包含 i。
- 9路 GTP 左上为 A9，右下为 J1，列名跳过 I。
- KataGo policy 的盘面部分按从左上到右下的行优先顺序排列，最后另有 pass 项。
- 若采用的棋盘库使用不同原点或行列顺序，增加明确适配，不能直接假定相同。

## 10. 最小模块和配置

以易读的少量文件为主，建议如下；不要求为了目录漂亮继续拆分：

| 文件 | 职责 |
| --- | --- |
| main.py | 命令行、参数和总流程 |
| sgf_io.py | 读取局面 SGF、导出候选棋谱 |
| terminal_loss.py | 黑白固定终盘点位 loss |
| katago_loss.py | 本地引擎生命周期、查询和动态点位 loss |
| board.py | 棋盘、合法性、提子与坐标适配 |
| heuristic_search.py | 搜索节点、累计计分、全局逐层保留候选 |
| config.toml | 引擎路径、每层保留数、预算、规则及惩罚系数 |
| tests/ | 有意义的关键行为和小规模集成验证 |
| README.md | 安装依赖、模型配置、使用方法、限制和验证状态 |

必要配置包括：KataGo可执行程序、模型路径、官方分析配置、规则、贴目、每层保留数、最大手数、可选精确手数、终盘整体系数、临时落子基础罚分、面积系数、其他空点罚分、终盘异色点罚分，以及概率数值下限。

所有初始参数均为可修改的示例，不能声称已经调优。终盘整体系数为0时应能运行纯KataGo代价的对照。模型权重和可执行程序由本地配置提供，不嵌入源码。

推荐实现的目标调用接口如下，这不是当前已经存在的命令：

```bash
python main.py --input position.sgf --output reconstructed.sgf --config config.toml --heuristic-width 64 --max-moves 160
```

其中，input 指定局面 SGF；output 指定候选棋谱输出；config 指定配置；heuristic-width 指定每层保留数；max-moves 指定搜索手数上限。已知手数可另用 --known-moves 提供。示例的64和160仅为调用格式演示，不是性能承诺。

## 11. 验证与验收

先完成一个小规模可运行闭环，再扩展性能与实验。核心验证包括：

- SGF输入输出和坐标往返一致，覆盖角点与边界。
- 提单子、提多子和一手提多块的盘面更新正确。
- 终盘空区连通、面积与边界颜色正确，黑白地图全程固定。
- 当前候选不同，KataGo动态地图分别查询；一份父地图能给该父节点的所有子着手评分。
- 在可控的替代引擎输出下，搜索按累计分数全局保留 n 条，不误用最新一手分数。
- 候选分支互不污染，已知手数剪枝不误删可行路径。
- 成功输出的SGF独立重放后与目标逐点相同；预算耗尽能明确报告未找到解。

真实 KataGo 验证与使用替代策略输出的逻辑测试分开报告。若机器上尚未配置模型，不能把替代测试说成真实推理成功。

数据制作可从完整真实SGF生成输入，但必须重放后新建只含终盘的摆子SGF；原始顺序另存，仅供评测。按整盘对局划分调参与测试集合，同盘的截断或对称版本放在同一集合。不能用模型自己的 loss 变小作为“恢复更准确”的唯一证据。
